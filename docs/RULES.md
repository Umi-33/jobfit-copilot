# V0 规则说明

## 评分结构

总分由以下部分组成，最后限制在 0 到 100 之间：

- `skill_score`：最高 30 分，计算用户已具备技能与岗位技能关键词的匹配。
- `experience_score`：最高 20 分，计算工作年限与岗位经验要求的匹配。
- `project_score`：最高 20 分，计算真实项目与岗位需求的匹配。
- `basic_score`：最高 15 分，计算城市、学历、薪资底线等基础条件。
- `bonus_score`：最高 10 分，计算 AI 工具落地、AIGC 内容管线、数据可视化等贴合岗位的加分项。
- `risk_score`：负分项，用于扣除硬性风险。

## 高价值匹配项

以下能力可以作为主要加分项：

- Vue3
- JavaScript
- Python
- FastAPI
- LLM API
- Prompt
- JSON/CSV
- ECharts
- 数据可视化
- AI 工具落地
- AIGC 内容管线

## 可补充了解项

以下能力只能作为小幅加分或缺口提醒，不能高估匹配度：

- React
- Next.js
- TypeScript
- Docker
- Linux
- LangChain
- RAG
- 生产级 Agent 框架

如果 JD 明确要求生产级 RAG、Agent 框架、向量数据库、复杂工程部署能力，而用户画像没有对应真实经历，系统必须标记为缺口，不能给出高匹配结论。

## 风险优先级

硬性风险优先于普通匹配项：

- 培训贷、先交费、付费培训：高风险，强扣分。
- 纯销售、电销、地推：高风险，强扣分。
- 薪资上限低于用户底线 8000：高风险，强扣分。
- 单休、大小周：明显风险，中高强度扣分。
- 运营占比高、KPI、强抗压：中等风险，扣分并提醒。

当出现高风险项时，即使技能匹配较好，也不能输出强推荐。

## 评分原则

1. 规则评分必须可解释，匹配项、缺口和风险项都要返回原因。
2. 只基于用户画像中的真实能力和项目做判断。
3. 不生成虚假经历。
4. 不把用户包装成成熟 Agent/RAG 工程师。
5. Mock LLM 只负责表达建议，不参与最终评分。
